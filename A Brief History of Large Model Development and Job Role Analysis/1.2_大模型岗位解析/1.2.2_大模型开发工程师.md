**大模型开发工程师**（LLM Application / Platform Engineer）位于算法能力与实际业务场景之间。如果说“算法工程师”负责把模型“炼好”，那么“开发工程师”则负责把模型的能力“封装、编排、工程化”，使其变成高可用、低延迟、可观测且能解决实际商业问题的软件系统。

---

### 一、 岗位定位与核心职责

大模型开发工程师的核心定位是：**以大模型为核心算力底座，构建企业级 AI 原生应用、智能体（Agent）系统及底层 LLM 中间件平台。**

1. **企业级 RAG（检索增强生成）系统开发：**
* 设计并落地非结构化数据（PDF、Word、表格、音视频）的解析与清洗 Pipeline。
* 实现多路召回（向量检索 + 全文检索 + 知识图谱）、重排（Rerank）及上下文组装机制，解决大模型在私域知识上的“幻觉”与数据时效性问题。


2. **智能体（Agent）架构设计与工具链集成：**
* 构建具备任务规划（Planning）、长期/短期记忆管理及多步反思能力的 Agent 工作流。
* 负责大模型与企业内部 API、数据库及外部生态的连接，落地 **MCP（Model Context Protocol）** 等标准化工具调用协议。


3. **LLM 服务网关与工程化基础设施（LLMOps）：**
* 开发模型网关（AI Gateway），实现多模型统一路由、鉴权、限流、熔断降级及 Token 级计量计费。
* 搭建推理服务的容器化部署与弹性扩缩容架构，优化高并发下的吞吐量与首字延迟（TTFT）。


4. **自动化评测、安全护栏与可观测性建设：**
* 构建端到端的线上评估体系（LLM-as-a-Judge），追踪回答准确率、幻觉率与召回率。
* 部署输入/输出安全护栏（Guardrails），防范提示词注入（Prompt Injection）及敏感数据泄露。



---

### 二、 关键技术能力要求

* **扎实的后端与系统架构能力：** 精通 Python（异步并发 `asyncio`、FastAPI）或 Go/Java，具备高并发分布式系统、微服务设计及缓存/消息队列调优经验。
* **深度掌握 LLM 应用开发范式：** 精通 Prompt Engineering（结构化输出、思维链引导、Few-Shot 动态采样）、Function Calling 机制及复杂状态机工作流设计。
* **检索与数据工程能力：** 深入理解文本分块（Chunking）策略、Embedding 向量空间特性，熟练操作向量数据库与混合搜索引擎，具备处理复杂版面文档解析的能力。
* **工程化部署与性能调优：** 熟悉 Docker/Kubernetes 容器编排，了解主流推理引擎（如 vLLM、SGLang）的 API 特性、流式输出（SSE）协议及显存/并发参数配置。

---

### 三、 典型工作流

大模型开发工程师的研发链路强调“快速原型—效果评测—工程加固—线上闭环”：

```
[业务场景拆解与交互设计]
       ↓
[知识库与数据管线构建] (文档解析 / 切片 / 向量化入库)
       ↓
[核心链路编排] (Prompt 工程 / RAG 检索链 / Agent 状态机与 MCP 工具接入)
       ↓
[自动化基准测试与安全校验] (构建 Golden Dataset / 幻觉与注入测试)
       ↓
[服务封装与网关集成] (FastAPI 流式接口 / 多模型路由 / 限流与缓存)
       ↓
[线上可观测性与持续迭代] (全链路 Trace 追踪 / Badcase 收集与规则热更新)

```

---

### 四、 常见技术工具与平台

* **应用与智能体编排框架：** LangChain, LangGraph（复杂有向图状态机）, LlamaIndex（数据与检索中心）, Semantic Kernel, AutoGen。
* **低代码 / 视觉化工作流平台：** Dify, Coze, FastGPT（常用于快速原型验证与业务侧协同）。
* **向量数据库与检索组件：** Milvus, Qdrant, PostgreSQL (pgvector), Elasticsearch, FAISS。
* **推理服务与模型网关：** vLLM, SGLang, Ollama, LiteLLM（统一多模型接口）, One API。
* **可观测性与评测工具：** LangSmith, Langfuse, Phoenix (Arize), Ragas（RAG 专项评估）。

### 五、 岗位价值与发展方向

#### 1. 岗位核心价值

* **打通 AI 落地的“最后一公里”：** 消除基座模型通用能力与企业复杂业务逻辑之间的鸿沟，直接决定 AI 产品的用户体验与商业闭环。
* **降本增效的工程杠杆：** 通过语义缓存（Semantic Cache）、大小模型路由分发（Router）与上下文压缩技术，在保障效果的前提下将企业的推理 Token 成本降低数倍。

#### 2. 职业发展路径

* **技术专家路线（AI 应用架构师 / LLMOps 架构师）：** 专注于超大规模多智能体协同架构、企业级 AI 中台建设、高并发低延迟推理网关及全链路可观测基础设施。
* **工程管理与业务融合路线（AI 研发负责人 / 解决方案架构师）：** 深入金融、政务、医疗、跨境电商等垂直行业，主导企业级数字化与智能化重构，成为兼具业务洞察与前沿工程能力的复合型技术管理者。
