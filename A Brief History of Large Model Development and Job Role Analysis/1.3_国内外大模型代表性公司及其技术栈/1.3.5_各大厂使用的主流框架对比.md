在大模型（LLM）工业化落地的全生命周期中，各大科技厂商（如 OpenAI、Anthropic、Google、Meta、阿里、字节、华为、DeepSeek 等）根据自身的算力底座（NVIDIA GPU、Google TPU、华为昇腾 NPU）与业务场景，形成了高度专业化的框架选型矩阵。

以下从**训练框架、推理框架、部署管理工具**三大核心维度，详细剖析主流框架的技术特性及各大厂的选型逻辑。

---

### 一、 大模型训练框架（Training Frameworks）

大模型训练的核心痛点在于**千亿级参数带来的显存墙（Memory Wall）**以及**万卡集群下的通信瓶颈**。主流方案已从早期的单机并行演进为“3D 并行（数据+张量+流水线并行）+ 零冗余优化（ZeRO）”的组合架构。

#### 1. 核心主流框架解析

* **PyTorch + FSDP (Fully Sharded Data Parallel)：**
* **定位：** 全球算法研发的绝对事实标准，Meta 主导，灵活性极高。
* **技术特点：** 原生集成 FSDP（类似 ZeRO-3 的参数分片策略）与 `torch.compile` 图编译优化。
* **大厂生态：** **Meta（Llama 系列）**、**OpenAI** 早期及中小型创新研发的核心底座，适合快速实验与新架构探索。


* **Megatron-LM (NVIDIA)：**
* **定位：** 超大规模 Transformer 预训练的“重型武器”。
* **技术特点：** 深度绑定 NVIDIA 硬件与 NCCL 通信库，将张量并行（TP）、流水线并行（PP）、序列并行（SP）与专家并行（EP）优化到了硬件极限。
* **大厂生态：** 几乎所有使用 NVIDIA 万卡集群训练千亿/万亿参数基座的大厂（如 **xAI、Mistral、智谱AI、百度、阿里** 等）在预训练阶段均重度依赖 Megatron-LM 或其深度魔改版本（如 **Megatron-DeepSpeed**）。


* **DeepSpeed (Microsoft)：**
* **定位：** 显存优化与中大规模训练的“瑞士军刀”。
* **技术特点：** 首创 **ZeRO（Zero Redundancy Optimizer）1/2/3** 阶段显存切分与 CPU/NVMe Offload（卸载）技术，大幅降低单卡显存门槛，同时对指令微调（SFT）与强化学习（RLHF）支持极佳。
* **大厂生态：** 广泛用于后训练对齐（SFT/DPO/GRPO）及垂直领域微调场景，常见于各大云厂商的托管微调平台（如阿里云百炼、火山方舟）。


* **JAX + XLA (Google) & MindSpore (华为)：**
* **定位：** 针对专用异构芯片深度绑定的全栈框架。
* **技术特点：** **JAX** 结合 XLA 编译器在 Google TPU 集群上展现出极致的自动微分与算子融合效率；**MindSpore（昇思）** 则针对华为昇腾（Ascend）NPU 架构实现了图算融合与多维混合并行。
* **大厂生态：** **Google（Gemini 系列）** 与 **Anthropic**（部分基于 TPU 集群）重度使用 JAX；**华为（盘古大模型）** 及国内采用全国产化算力底座的企业（如 **科大讯飞“飞星一号”**）则依托 MindSpore 或昇腾适配版 PyTorch 进行训练。


* **自研魔改框架（如 DeepSeek HAI-LLM / 字节 MegaScale）：**
* **特点：** 头部大厂为榨干集群算力，通常基于 Megatron 底层进行深度重构，解决跨节点通信阻塞、FP8 混合精度训练稳定性以及 MoE 路由负载均衡问题（如 DeepSeek 针对 MLA 与细粒度 MoE 定制的训练引擎）。



#### 2. 主流训练框架对比表

| 框架名称 | 主导厂商 | 核心技术优势 | 硬件绑定性 | 典型大厂应用场景 |
| --- | --- | --- | --- | --- |
| **PyTorch (FSDP)** | Meta / 开源社区 | 生态最完善、动态图易调试、原生支持参数分片 | 通用（CUDA/ROCm/NPU） | Meta Llama 研发、算法原型探索、中小型微调 |
| **Megatron-LM** | NVIDIA | 3D并行+专家并行极致吞吐、NCCL 通信优化极深 | 强绑定 NVIDIA GPU | 国内外大厂千亿/万亿参数基座预训练 |
| **DeepSpeed** | Microsoft | ZeRO 显存优化、CPU Offload、生态集成度高 | 较通用（主攻 NVIDIA） | 算力受限下的微调（SFT）、强化学习（RLHF） |
| **JAX / XLA** | Google | 函数式编程、自动并行切片、XLA 编译效率极高 | 强绑定 Google TPU | Google Gemini、Anthropic Claude（TPU 集群） |
| **MindSpore** | 华为 | 动静统一、原生适配昇腾达芬奇架构与超节点互联 | 强绑定华为昇腾 NPU | 华为盘古大模型、国内政务/央国企国产算力集群 |

### 二、 大模型推理框架（Inference Engines）

大模型推理分为 **Prefill（计算密集型预填充）** 和 **Decode（访存密集型逐词解码）** 两个阶段，核心优化指标是**首字延迟（TTFT）**、**单 Token 生成延迟（TPOT）** 与**系统总吞吐量（Throughput）**。

#### 1. 核心主流框架解析

* **vLLM：**
* **核心技术：** 首创 **PagedAttention（分页注意力）** 解决 KV Cache 显存碎片化问题（显存利用率提升至 90% 以上），支持 **Continuous Batching（连续批处理）** 与分布式张量/流水线并行。
* **大厂生态：** 开源社区与云厂商最主流的通用推理引擎，模型兼容性极佳（新模型发布几乎当天支持），广泛部署于国内外各大云平台与企业私有化环境。


* **SGLang：**
* **核心技术：** 首创 **RadixAttention（基数树注意力）**，将多轮对话历史与系统提示词（System Prompt）的 KV Cache 保存在基数树中实现跨请求自动前缀复用；同时具备基于正则/语法的状态机**约束解码（Structured Output）**。
* **大厂生态：** 专为 **Agent 工作流、多轮对话、复杂代码生成及 JSON 结构化输出**打造。包括 **xAI、DeepSeek 官方推理集群** 以及字节、阿里等大厂在高并发 Agent 场景中均重度采用 SGLang 架构。


* **TensorRT-LLM (NVIDIA)：**
* **核心技术：** 将模型提前编译为高度优化的 TensorRT 底层执行引擎，融合 FlashAttention、自定义 CUDA Kernel 与极致量化（FP8 / FP4 / INT4 AWQ/GPTQ），将单卡硬件性能压榨至物理极限。
* **大厂生态：** 适用于对延迟要求极其苛刻（如实时语音对话、高频金融业务）且算力充足的生产环境（如 **OpenAI、Perplexity** 等头部服务商的在线推理集群）。缺点是模型编译耗时较长、定制灵活性略逊于 Python 生态框架。


* **LMDeploy (书生·浦语) & 昇腾 MindIE：**
* **核心技术：** **LMDeploy** 具备自研 TurboMind C++ 推理引擎与高效 KV Cache 量化，且对多模态视觉语言模型（VLM）支持极强；**MindIE** 则是华为针对昇腾芯片打造的原生高速推理引擎。
* **大厂生态：** 国内多模态应用及国产算力卡（昇腾 910B/C）大规模推理落地的核心选择。


* **llama.cpp / Ollama：**
* **核心技术：** 纯 C/C++ 编写，支持 GGUF 量化格式与 CPU+GPU 混合异构推理，零外部依赖。
* **大厂生态：** 主要应用于端侧设备（AI PC、手机离线模型）以及开发者本地快速原型验证。



#### 2. 主流推理引擎对比表

| 推理框架 | 核心技术亮点 | 吞吐与延迟表现 | 易用性与灵活性 | 最适用的业务场景 |
| --- | --- | --- | --- | --- |
| **vLLM** | PagedAttention、Continuous Batching | 吞吐均衡、通用场景表现稳定 | 极高（新模型适配最快） | 通用企业级高并发 API、多模型统一托管 |
| **SGLang** | RadixAttention 前缀复用、约束解码 | 多轮对话/Agent 场景吞吐领先 2-5 倍 | 较高（Python 编写调度器，易二次开发） | 多轮对话、复杂 Agent 工作流、长文档前缀复用 |
| **TensorRT-LLM** | 静态图预编译、算子融合、FP8/FP4 量化 | 单次推理延迟（TTFT）最低、极限吞吐最高 | 较低（预编译耗时长，强绑定 NVIDIA） | 实时语音交互、超大规模固定模型线上主力服务 |
| **LMDeploy** | TurboMind 引擎、KV Cache 4bit 量化 | 多模态与长上下文吞吐表现优异 | 较高（兼容国产硬件与 NVIDIA） | 视觉语言多模态（VLM）服务、国产算力混部 |
| **llama.cpp** | 纯 C/C++ 无依赖、GGUF 极致低比特量化 | 端侧 CPU/NPU 内存占用极低 | 极高（跨平台一键运行） | 手机/PC 端侧离线部署、边缘计算设备 |

### 三、 部署管理与集群调度工具（Deployment & Orchestration）

当推理引擎封装好单机或单实例服务后，大厂需要通过集群调度、服务网格与模型网关，将成百上千个模型实例编排为高可用、弹性伸缩的企业级基础设施。

#### 1. 核心架构分层与代表工具

* **底层云原生集群编排：Kubernetes (K8s) + NVIDIA GPU Operator / Volcano**
* **作用：** 整个 AI 基础设施的底座。负责 GPU 硬件驱动自动注入、拓扑感知调度（确保同一模型的张量并行实例调度在同一台拥有 NVLink 高速互联的物理机上）以及节点故障自愈。华为开源的 **Volcano** 批量调度器在国产云厂商中应用极为广泛。


* **分布式 AI 服务编排：Ray Serve & KServe**
* **Ray Serve：** 基于 Python 分布式框架 Ray 构建的模型服务库，原生支持多模型流水线编排（如“意图识别小模型 $\to$ 向量检索 $\to$ 旗舰大模型”串联）、动态副本扩缩容及零停机滚动升级，深受 **OpenAI、Cohere 及各大硅谷独角兽**青睐。
* **KServe (CNCF 孵化项目)：** 专为 Kubernetes 设计的标准化无服务器（Serverless）推理平台，原生支持“按请求并发数自动缩容至零（Scale-to-Zero）”与金丝雀灰度发布，是公有云厂商构建模型托管平台（MaaS）的常用组件。


* **工业级推理服务框架：NVIDIA Triton Inference Server**
* **作用：** 支持将 TensorRT-LLM、vLLM、ONNX Runtime 等多种后端引擎统一封装为标准的 gRPC/HTTP 接口，内置动态批处理、多模型并发驻留单卡（MIG 切分）及细粒度硬件指标暴露（Prometheus 监控），是传统大厂生产级部署的基石。


* **企业级 AI 网关（AI Gateway）：LiteLLM / Kong AI Gateway / One API**
* **作用：** 位于业务应用与底层推理集群之间的流量入口。核心解决**多模型统一协议转换**（将 Claude、Gemini、Qwen、DeepSeek 统一为 OpenAI 接口格式）、**Token 级限流与计费**、**语义缓存（Semantic Cache）**以及**故障自动熔断降级**（主模型超时自动切换备用集群）。



#### 2. 主流部署管理工具对比表

| 工具/平台 | 架构层级 | 核心治理能力 | 优势与局限 | 大厂典型应用场景 |
| --- | --- | --- | --- | --- |
| **Kubernetes + Volcano** | 底层资源调度层 | GPU 拓扑感知调度、队列配额、弹性扩缩容 | 云计算绝对底座，但配置与运维复杂度高 | 所有大厂万卡训练与推理集群的统一算力底座 |
| **Ray Serve** | 应用/服务编排层 | 多模型复杂 DAG 流水线编排、精细化副本扩缩 | Python 原生友好，极适合多智能体与多模型协同 | 复杂 RAG/Agent 链路编排、多模型混合推理服务 |
| **NVIDIA Triton** | 推理服务容器层 | 多后端统一封装、动态批处理、硬件级指标监控 | 生产稳定性极高，对 NVIDIA 生态支持最完善 | 金融、电信、互联网大厂的高可用核心推理集群 |
| **KServe** | 云原生 Serverless 层 | 标准化模型生命周期管理、Scale-to-Zero、灰度发布 | 与 K8s 生态无缝集成，适合多租户隔离 | 公有云 MaaS（模型即服务）平台底座 |
| **LiteLLM / AI 网关** | 流量与业务治理层 | 多模型路由、Token 计费限流、语义缓存、安全护栏 | 轻量易接入，有效降低业务侧模型切换成本 | 企业内部统一 AI 中台入口、多云多模型容灾路由 |

### 四、 总结：大厂典型全栈技术选型范式

在实际生产中，各大厂并非单一使用某款工具，而是采用“分层解耦、组合拳”的架构：

1. **底层训练：** 使用 **Megatron-LM**（NVIDIA 集群）或 **JAX / MindSpore**（TPU/昇腾集群）完成万亿级基座预训练，再切换至 **DeepSpeed / FSDP** 完成高灵活性的后训练（SFT/GRPO）对齐。
2. **推理加速：** 对于极致低延迟的旗舰在线服务（如实时语音、主力 API）采用 **TensorRT-LLM** 静态编译优化；对于复杂多轮对话、代码生成与 Agent 平台，采用 **SGLang** 或 **vLLM** 实现动态前缀复用与高吞吐并发。
3. **生产治理：** 底层由 **Kubernetes + Volcano** 管理异构算力池，中间通过 **Triton Server** 或 **Ray Serve** 托管推理引擎实例，最上层挂载 **AI Gateway（如自研网关或 LiteLLM）** 实现多模型路由、语义缓存与全链路可观测性监控。
